# HW5 預訓練一個小 GPT，再載入 GPT-2 權重（11/16 – 12/06，寬限至 12/13）

筆記本：[hw5/hw5_pretraining.ipynb](hw5/hw5_pretraining.ipynb)　取材：Raschka《Build a Large Language Model (From Scratch)》第 5 章，套件 `llms-from-scratch`　難度：原理型｜核心段落約 1.5–2 小時，選做另計　需要 T4 GPU（訓練約 2–3 分鐘）

## 目標

把第 7–9 單元的「機器學習三步驟 → 訓練訣竅 → 預訓練」在一個 1.24 億參數的 GPT 上跑一遍：資料怎麼切成輸入／目標、損失從 ln(50257) 開始下降、什麼叫過度擬合、temperature 與 top-k 怎麼改變輸出（選做）；最後載入 OpenAI 真正訓練好的 GPT-2 權重，體會「同樣的層數與維度、不同的參數」差多少。

## 步驟

只有核心段落（第 0–3、5 節）會出題；第 4 節為選做，不計分、可跳過。

### 第 0–1 節 資料
- 《The Verdict》短篇小說（固定 commit 下載並驗證 SHA-256）：字元數、GPT-2 tokenizer 的 token 數；90／10 切訓練與驗證；`create_dataloader_v1`（長度 256、步幅 256）→ 訓練 token 數、驗證 token 數、批次數。
- 確認目標就是輸入右移一格。

### 第 2 節 訓練前的損失
- 隨機初始化的模型在訓練集與驗證集的交叉熵損失，對照 ln(50257)。
- ✍️ 為什麼接近 ln(50257)？初始損失接近 ln(50257)，對應多大的正確 token 機率？

### 第 3 節 訓練 10 個 epoch
- AdamW、學習率 4e-4；每 5 步評估一次並印出接龍樣本；畫損失曲線。
- ✍️ 訓練／驗證損失從哪裡分開？這叫什麼？為什麼一定會發生？

### 第 4 節 解碼策略（選做）
- 同一個開頭，比較 greedy、temperature 1.5、top-k 5。

### 第 5 節 載入 GPT-2 124M
- 從 Hugging Face 下載固定版本的 safetensors（548 MB、160 個張量，驗證 SHA-256），對應到我們自己的 `GPTModel`（改用 `qkv_bias=True`、上下文 1,024 以符合原始 GPT-2；注意 Q/K/V 合併矩陣要拆開、線性層要轉置、輸出層與詞嵌入共享）。
- 算 GPT-2 在《The Verdict》上的損失；三個開頭接龍，其中一個是中文。
- ✍️ 我們無法確認 GPT-2 的訓練資料是否含這篇 1908 年的小說；除了「可能看過」，它的損失遠低於我們的模型還有什麼合理的解釋？中文為什麼是亂碼、7 個字要十幾個 token？

## 常見問題

- **訓練損失和書上不完全一樣？** 正常：GPU 的浮點運算順序不同；趨勢（訓練下降、驗證先降後升）是一樣的。
- **記憶體不足？** 把 `GPT_CONFIG_124M["context_length"]` 維持 256 即可；T4 綁綽有餘。
- **想用更多資料訓練？** 見 repo 的 `ch05/03_bonus_pretraining_on_gutenberg`。
