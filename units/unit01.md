## 重點提示（Highlights）

- **語言模型 = 文字接龍**：把輸入當成未完成的句子，反覆預測「下一個 token」，直到接出結束符號 `[END]`。
- **token** 是模型輸入輸出的基本單位，來自固定的詞彙表；不一定等於一個字或一個單字。
- 模型每一步輸出的是**機率分佈**；聊天產品通常依機率**抽樣**（擲骰子）決定輸出，所以同樣的問題每次答案可能不同（若改用 greedy 等確定性解碼，答案就固定）；但機率極低的接龍（「三明治」）幾乎不會出現。
- 要接得好需要**語言知識**（較易學）和**世界知識**（無窮無盡，且會隨條件改變，例如 0.5 大氣壓下的沸點）。
- 模型是一個參數極多的函數 f，**參數是從資料學出來的**，不是人工設定。
- 三個學習來源：網路資料 → **預訓練**；標註資料 → **微調**；使用者回饋 → **RLHF／對齊**。
- 多輪對話靠的是**把整段對話歷史再餵一次**；太長就會「遺忘」。**system prompt** 是服務商預先放在輸入前面的內容（日期、身分、規則）。
- **幻覺**不是故障：模型只能根據輸入選出「最像樣」的接龍，輸入資訊不足是幻覺的主要原因之一（其他來源還有訓練目標只獎勵「像」、低頻事實記不牢、模型忽略或誤用 context）。老師因此說「確保輸入資訊足夠是人類的責任」（下一單元的 Context Engineering）；即使資訊充分，高風險內容仍要外部驗證。
- **生成式 AI 的定義（本講框架）**：讓機器產生複雜而有結構的物件，把它拆成有限基本單位（token）的序列逐一生成。這是第 1 講採用的自迴歸框架，不是唯一路線。
- 影像與聲音：逐像素／逐取樣點接龍太貴（1024×1024 約 100 萬次），所以自迴歸路線用 **Encoder 壓成 token → 接龍 → Decoder 還原**；主流影像模型也常在連續 latent 上用 diffusion／flow 逐步去噪、不逐一接龍（第 12 單元）。
- **開放權重 vs 閉源**：老師說的「開源模型」（LLaMA、Mistral、Gemma、Qwen）嚴格說是「開放權重」——權重可下載、可在自己的環境執行與微調，但授權各不相同，不一定符合 OSI 的 Open Source AI 定義；閉源模型（ChatGPT、Gemini）只能透過供應商的聊天介面或 API 使用，部分供應商另提供託管式微調，但拿不到權重。

## 實例（Worked example）

問：「臺灣最高的山是哪座？」

1. 模型看到輸入後，算出下一個 token 的機率分佈：「玉」0.5、「是」0.3、「答」0.15、「三」0.0001……
2. 依機率抽樣（聊天產品的常見設定），假設抽到「玉」；把「玉」接上去，再算一次分佈 → 抽到「山」；再算 → 抽到 `[END]`，停止。
3. 因此可能得到「玉山」、「是玉山」、「答案是玉山」等不同答案，但幾乎不會得到「三明治」。

換成問：「請給我一篇討論這個主題的論文網址」——模型一樣會接出一個「看起來像網址」的字串，但它並沒有查證，這是幻覺最常見的來源之一。

## 動手練習（不計分，約 15 分鐘）

到任一聊天機器人（ChatGPT／Gemini／Claude 皆可）做三件事，並把觀察記在筆記裡，討論時會用到：

1. 同一個開放式問題（例如「用一句話介紹逢甲大學」）連問三次或按「重新生成」三次，比較差異。
2. 問「今天幾月幾號？」，再問「如果不能使用任何工具，你怎麼知道今天的日期？」。
3. 請它提供某個冷門主題的「參考書目與網址」，實際點開驗證是否存在。

**討論題**：從你的動手練習或過去經驗中，找一個生成式 AI「講得煞有其事卻是錯的」例子。請貼出你的提問與模型回答（節錄即可），並：

**回覆同學時**請至少做到其中一項：指出對方的解釋是否符合本單元原理；補充另一種可能的成因；或分享你用同樣問題得到的不同結果。

**教師引導重點**（供教師發文與週末小結使用）：
- 幻覺 ≠ 模型「說謊」，而是「選最合適接龍」機制的副作用：輸入資訊不足是主因之一，但資訊充分時模型也可能忽略或誤用 context。
- 減少幻覺的方向：提供資料（RAG）、要求引用、降低隨機性、要求不知道就說不知道、對高風險資訊做外部驗證——前幾項會在第 2、3 單元展開。
- 小結時可挑 2–3 篇精彩的貼文公開表揚，並把常見誤解（例如「模型有內建資料庫」）澄清一次。
