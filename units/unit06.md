## 重點提示（Highlights）

- **評量架構（有標準答案時）**：benchmark（一組輸入，附標準答案）→ 評分函數 e(輸出, 標準答案) → 彙整（通常取平均）。廣義的 benchmark 是標準化的任務、資料與評分流程，不一定有唯一標準答案——後面的 Arena、MOS 就是例子。使用者想知道「該用哪個模型」，開發者想知道「哪種資料／訓練方法好」。
- **怎麼對答案**：Exact Match 只適合答案形式固定的題目（選擇題）；連選擇題都有「模型輸出『答案是 b』」、「比較 A/B/C/D 機率 vs 模型想答 3」、「偏好猜 A」的問題；還要小心分數混雜了「看不看得懂指令」。
- **相似度指標**：BLEU（翻譯）、ROUGE（摘要）比對共同詞彙，「詼諧」對「幽默」會判 0；BERTScore 改比較 representation。
- **不要過度相信分數**：Goodhart's law；「鸚鵡」（照抄輸入）與「笨鸚鵡」在換句話說任務上打敗許多模型。
- **評量與幻覺**：「我不知道」得 0 分、硬猜有機會得分 → 訓練誘因讓模型學會硬猜，是幻覺被強化的原因之一（不是唯一原因）；解法：倒扣、依情境調整拒答。
- **沒有標準答案時**：請人類（Chatbot Arena）——但人在意「怎麼說」勝過「說了什麼」（長度、Markdown、表情符號 → style control），且花時間、花錢、再現性差；語音用 MOS 而非相似度。
- **LLM-as-a-judge**：先寫分析再給分與人類最相關；可用分數期望值；專門評分的模型叫 verifier，可當 RL 的 reward model（評估比生成容易）。偏見：偏袒自己的輸出、位置偏見 → **先小規模驗證再大規模使用**。
- **其他考量**：速度（first token 延遲、每秒 token 數）、價格、思考 token 划不划算；**木桶理論**——平均會掩蓋偶爾「暴走」的最壞情況。
- **要考什麼取決於你在意什麼**：單一任務／特定領域／通用模型；各家模型卡列的 benchmark 不同；GDPval 用 44 種職業的真實任務評量。
- **Prompt 會影響評量**：同一任務換 prompt 準確率天差地遠；比較模型時要多個 prompt 取平均；大海撈針測驗加一句提示就大幅改善。
- **資料洩漏**：模型在看過的考題上明顯較好，背不出題目不代表沒看過（GSM-8k 改寫版、LessLeak-Bench）。
- **惡意使用與偏見**：jailbreak（說服、角色扮演）、prompt injection（AI 助教、論文審查、AI 主播、代理人的 indirect injection）；「回答什麼」與「要不要回答」分開處理；換一個詞（男朋友／女朋友）回應差很多。

## 實例（Worked example）

任務：把課程講義的一句英文翻成中文。標準答案：「這個機制對效能至關重要。」模型輸出：「這項機制對表現極為關鍵。」（下表為**概念示意**，不是實測：BLEU、BERTScore、人類與 LLM 評分的實際數值取決於 tokenization、embedding 模型、評分提示與評審，這裡只呈現各指標的傾向。）

| 評分方式 | 結果（示意） | 為什麼 |
|---|---|---|
| Exact Match | 0 分 | 字面不同就是 0——顯然不合理。 |
| BLEU（詞彙重疊） | 很低 | 幾乎沒有相同的詞，但意思一樣。 |
| BERTScore | 高 | 兩句在模型內部的表示很接近。 |
| 人類評分 | 4／5 | 意思正確、語感稍硬。 |
| LLM-as-a-judge（先分析再給分） | 4／5 | 與人類接近；若只要求輸出數字，可能給出較不穩定的分數。 |

同一個輸出，不同評分方式結論不同；設計評量時要先想清楚「我在意的是什麼」，再選對得起這個目標的指標——並用少量人工檢查確認指標沒有失真。

## 動手練習（不計分，約 15 分鐘）

1. 到 <https://lmarena.ai/> 用同一個問題（例如「用 100 字介紹逢甲大學」）比較兩個匿名模型並投票；投完票再想一想：你是被「內容」還是「形式」（長度、排版、表情符號）影響？
2. 用兩種 prompt 問同一個模型同一道應用題：直接問；以及加上「請一步一步思考再給答案」。看答案是否改變——這就是「prompt 會影響評量」。
3. 問模型一件它不可能知道的事（例如你家寵物的名字或你上一單元的午餐），觀察它是硬猜還是說不知道。

3. **這個評量可能怎麼被「Goodhart」**：有沒有辦法不真正做好任務卻拿高分（像鸚鵡那樣）。
